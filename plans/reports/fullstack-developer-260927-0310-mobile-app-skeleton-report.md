## Deviations / real issues found and fixed

1. **pnpm strict node_modules broke `@react-native/jest-preset`'s asset-registry mapping.** `@react-native/jest-preset`'s bundled `moduleNameMapper` remaps `react-native/asset-registry` → the pre-"exports" path `react-native/src/asset-registry`, resolved via a custom resolver relative to whatever file requested it. Under pnpm's isolated `node_modules`, that resolution can't find `react-native` from inside the preset's own nested store location (confirmed empirically: `require.resolve` for the same specifier succeeds from `apps/mobile` but not from the preset's context). Fixed entirely inside `apps/mobile/jest.config.ts` (owned file): override that one `moduleNameMapper` entry with the real absolute path resolved via `createRequire(import.meta.url)` from the app's own working context. No repo-wide `.npmrc`/hoisting change was needed or made.
2. **`pnpm install` needed `@parcel/watcher`'s install script allowed.** pnpm auto-appended a placeholder to `pnpm-workspace.yaml`'s `allowBuilds`; set it to `true` (Metro's file watcher).
3. **`@testing-library/react-native@14.0.1`'s `render()` is now async** (returns `Promise<{...queries}>`, backed by the new `test-renderer` package instead of the deprecated `react-test-renderer`). Test updated to `await render(...)`.
4. **`app.config.ts` needed `owner: 'critterpass'`.** `eas init` reported the dynamic config couldn't be auto-patched and asked for this explicitly (the CLI user belongs to six Expo accounts, so disambiguation is required). Added; `eas init` then completed cleanly and set the project icon.
5. **Two real lint findings, fixed without touching root `eslint.config.js`** (out of ownership): `metro.config.js`'s two `require()` calls need a scoped `eslint-disable` (Metro loads this file as CommonJS regardless of the repo's ESM convention — the file itself is fine, only the syntax-level rule needed a documented, narrow exception). `app.config.ts`'s `process.env.APP_VARIANT` read typed as `any` in this project's tsconfig despite `@types/node` resolving correctly (verified `globals.d.ts`/`process.d.ts` are both in the `tsc --listFiles` output) — root cause not fully isolated, but the fix is the same pattern already used for `Constants.expoConfig.extra` in `index.tsx`: read into an explicit `unknown` and narrow with a literal-equality check before returning, which is strictly more defensive at an external-input boundary regardless of the underlying typing quirk.
6. **`expo-updates` is not installed.** EAS build logged (non-blocking): the `development`/`development-simulator` profiles reference update channels, but without the `expo-updates` package OTA updates cannot actually run yet. `runtimeVersion`/`updates.url` are configured per the spec; installing and wiring `expo-updates` is left for whichever later phase first exercises EAS Update, since nothing in this task publishes an update.
7. **iOS build logged (non-blocking):** `app.config.ts` is missing `ios.infoPlist.ITSAppUsesNonExemptEncryption`; only required before App Store Connect / TestFlight testing, not for simulator or ad hoc builds. Left for the phase that sets up store submission — declaring encryption usage is a product/compliance answer, not a default I should invent.
8. **`preview` EAS profile's `APP_VARIANT`** was not specified in the plan (only development/staging/production have bundle ids). Set it to `staging` with its own `channel: preview`, matching system-architecture.md's env table (preview reuses staging-like infra but gets its own EAS Update channel so PR builds don't clobber the main staging channel). Flagging this inference in case the founder wants a different mapping.
